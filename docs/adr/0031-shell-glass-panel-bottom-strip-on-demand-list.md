# 0031 · 外壳重设计：满铺画布 + 浮动玻璃面板 + 底部单条 + 按需标注列表

Status: 现行 · Date: 2026-09-04 · Scope: `index.html`、`src/workbench/`、`src/workbench/wb-tokens.css`、`scripts/build-wb-tokens.mjs`、`src/client/annotate.js`

Supersedes: ADR 0008（反模式清单里的“毛玻璃”一条，其余准则不动）、ADR 0010（暖纸画布）、ADR 0011（右栏结构与模式单钮）

**Decided**（owner 在评审板 `prototypes/shell-variants` 上两轮定；下面的引号内是 owner 原话）:

- **画布满铺，chrome 全部浮起来。** 画布铺满窗口，左栏不再占一栏宽度，改成浮在画布上的磨砂面板：材质
  `rgba(255,255,255,.88)` + `blur(20px) saturate(1.2)`，radius 14，投影 `--wb-sh-3`，距窗口边缘 12px。
  这一档材质是评审板的 F2，左栏、底部横条、弹出列表三处共用同一份取值（token `--wb-glass` / `--wb-glass-blur`）。
  左栏可拖宽保留。
- **顶部不放东西，浮动 chrome 收成底部居中的一条。** 一条胶囊横条，左端是 Pages 开关 + 页名 + 类型标，
  中间是 ‹ 1/6 › + map + 缩放 + 回中 + 导出，右端是 交互｜标注 两段控件 + 标注计数。左栏展开时下沿停在
  横条上方 12px。原来贴在画布左右边缘正中的两颗胶囊、以及右下角单独的 HUD，都删除。
- **右栏取消，画布上的钉子是标注的主体。** 钉子常显且与画面高对比（白描边 + 投影），评论卡只在 hover
  钉子时出现。列表按需开：点横条右端的计数钮弹出“这页的标注”，280 宽玻璃列表，锚在计数钮上方，
  行 hover 出“定位”，Esc 关。列表不能盖住被定位的那个气泡——高亮气泡的层级在列表之上，“定位”时
  画布把目标挪到列表没盖住的区域。ADR 0026 的 section note detail 面板改用同一个按需位置，
  不再需要一栏常驻的容器。
- **画布纸换冷中性** `#f5f6f8`（Radix slate 2–3 之间），取代 ADR 0010 的暖纸 `#faf8f4`；双线网格各淡一档
  （120px 线 accent 13% → 9%，24px 线 6% → 4%）。
- **字阶四档**：面板标题 15/600，列表行 13/500 用正文色，正文 12.5，元数据 11 mono；选中行底 = accent 10%，
  hover = 4%。

**Why**: owner 每天用这个工具，本轮的起点是他自己对着桌面 1600×1000 六个状态的截图把现状看了一遍，
问题都不是单点：左栏头部第一眼看到的是“已连接”，不是产品名和搜索；26 行同一档字，选中和 hover 是同一个
灰底，分不清；右栏 308px 常态九成是空的，owner 的话是“其实我很少看右边栏”“大部分时候只需要看画布上的
标注气泡”“只有当我要浏览 ‘这页还剩什么’ 时才需要打开列表”；暖纸配蓝灰网格再配纯白 chrome，冷暖打架；
收起态两颗胶囊在画布左右边缘正中、HUD 在右下，三个浮动元素散在三个位置。所以本轮改的是外壳的组织
方式——一块面板、一条横条、一个按需位置——不是换一层皮。

材质这一档是量出来的。第一轮只给了白 82%（blur 24）和白 88%（blur 20）两档，owner 的判断是“这两个对我来说
没有太大的区别，也许你应该给我几个 ‘差别更大’ 的选项”：两档都压在白色内容上，看不出差别。第二轮把四档
一起压在深色内容上——F1 实白面板（对照）、F2 磨砂 白 88、F3 玻璃 白 62、F4 液态玻璃 白 38——取舍这才看得见。
第二轮 owner 的话是“F2 + G1 + H（很不错，但是要修一下，看我的批注）”，两条批注就是上面钉子高对比常显、
以及列表不许盖住被定位气泡这两点。

**Rejected**:

- **F4 液态玻璃（白 38）**：最透的一档，正文行落在深色内容上时读不清。这条也是第一轮就定下的方向的
  具体化——玻璃做的是材质感，不是真透视，字必须读得清；真透视因此一并否掉。
- **F3 玻璃（白 62）**：透视强度对一块常驻的面板过高。左栏是一直在那里的东西，不是偶尔掠过的浮层。
- **顶部成簇**（B1 最小 / B2 并入导航）：owner 的话是“既然我们已经有一个小导航栏在下方了，不如让收起时
  也收起到下方的横条（左右侧栏）？你画一下我看看”。收纳位置因此从顶部移到底部。
- **G2 三段**（左中右各一颗胶囊）：与 G1 单条对比后选 G1，三个浮动元素三个位置正是现状的毛病。
- **右栏默认收起、切到标注模式或当前页有标注时自动展开**（第一轮的选项 4A）：第二轮改成右栏取消，
  本条随之作废。

**Consequences**:

- token 层先行落地（`--wb-glass` / `--wb-glass-blur` / `--wb-grid-1`/`2` / 四档 `--wb-t-*` / `--wb-sel` /
  `--wb-chrome-gap` 12 / `--wb-strip-h` 38 / `--wb-r-glass` 14），生成器与 `wb-tokens.css` 是唯一取值源，
  `index.html` 不再写字面 color-mix。
- fit-to-view 与 focusFrame 的可用区要减掉浮动面板与横条的占位；e2e 断言按 ADR 0023 比 boundingBox，
  不靠可见性断言。
- 注入端 `#ann-sidebar` 换同一档玻璃，两端材质一致。
- 错误面板去虚线边框，改实底 + `--wb-sh-3`——虚线框读起来像拖放区。
- 预览 Light/Dark 从左栏底部搬进预览设置，改名“预览主题”：它切的是被预览页面的主题，不是界面主题。
- chrome 暗色主题显式缓期：整套 `--wb-*` 要翻倍，玻璃材质在暗底上要单独调，ADR 0011 的单主题决定要重开。
  启动信号 = owner 在暗色环境里用 workbench 觉得刺眼。
