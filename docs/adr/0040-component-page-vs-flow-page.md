# 0040 · 组件页与交互页：变体放 section，不放进帧里

Status: 现行 · Date: 2026-10-10 · Scope: `skills/pinpoint-build/SKILL.md`、`docs/board-schema.md`（变体组一节已删）
Supersedes: [0039](0039-variant-groups.md)

**起因**：0039 让一个帧带多个变体（展开 / 勾选 / 收起），当天上线。用起来，变体仍和交互流程混在同一张画板里，
流程板臃肿；而变体要在手机界面里才看得出效果（单看组件的 comp 墙用得很少）。

**Decided**（2026-10-10 owner，grilling）：

- 概念拆分，底层不加机制。**组件页**：每个 section 服务一个组件，里面是同一个手机界面下它的几个变体，
  一个变体一个普通帧。**交互页**：正式流程，每个关键帧只放定下来的那个。
- 在组件页评审选定后，**复制**一份进交互页，之后各改各的。不做活引用、不做 `use()`、不做“换变体标注即失效”。
- 整屏变体组（`variants` 条目、展开 / tickbox / 组框、`A2a` 式编号、选中偏好）整体退役；
  含 `variants` 的 board 在校验时报“变体组已退役”。
- `shell: "comp"` 的组件墙保持现状，不扩展。
- 保留：`ppnt build` 对手写编号式 title（K11、B3）的提示（ADR 0026 的问题仍在）。

**否掉的**：
- 组件级变体 + 帧里 `use('组id')` + 选中进 `board.json`：流程帧要读组件页的选择，加了一层引用与失效规则；
  而 owner 要的是整屏上下文里看变体，不是 props 级复用。
- 活引用（交互页的一屏是组件页变体的别名）：流程里的屏几乎总要改数据与前后文，引用立刻要脱钩。

**代价**：评审选定后要手动复制一份；组件页与交互页之间没有机器可查的关联。
